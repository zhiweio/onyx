# 财税与经营风险分析报告

写作指南。本模板是契约式:版式由渲染器统一生成,章节结构由你按证据组织。
契约约束"必须为真、必须包含",不约束章节排布——同一任务不同公司的报告,
结构应当相似但不雷同。

## 必答问题(报告必须逐条回答)

1. 五年里哪些指标在变好,哪些在恶化?
2. 利润是不是真的?现金能不能验证利润?
3. 税交得对不对、稳不稳?优惠能不能持续?
4. 钱花在哪了,还够不够?债扛不扛得住?
5. 哪些风险必须马上处理,哪些只需持续监控?
6. 下一步 30 天、90 天做什么?

## 必备产物(缺一不过质量门)

- 核心指标看板:20 个以上指标五年横排,用 ` ```kpi ` 指标条呈现关键 6~8 个;
  派生指标用公式算,不手填;配 5~7 条关键洞察。
- 三表透视要点:利润表、资产负债表、现金流量表五年并列,异动科目逐条点评并对应事件。
- 税负与现金流专项:实际所得税率 vs 法定税率、整体税负率、收现比、净现比、
  自由现金流;税收优惠资格与到期时间。
- 风险矩阵:TX-xx(财税)/ OP-xx(经营)全部条目,编号 / 风险点 / 等级 / 评分 / 处置建议。
- 整改清单:30 日 / 90 日 / 持续监控三层,每条回扣风险编号。
- 期后事项:单独成章,标注「未经审计,仅作趋势观察」,不并入五年表。
- 数据缺口:拿不到写「未获取」并写原因。
- 免责声明:保留在报告末尾。

## 叙事脊柱(引导,不是硬性章节)

总览(执行摘要 + 核心看板)→ 数据与趋势(三表透视 + 专项分析)→
风险(识别 + 矩阵 + 专题)→ 建议与结论(整改 + 期后 + 免责)。

在此弧线内:章节可增删、合并、重命名,子结构自由;公司特有重大事项
(定增终止、商誉高企、审计机构更换、实控人变动等)应增设专题章;
风险条数由证据决定(财税约 4~10 条,经营约 3~8 条),不凑数。

## 组件与图表

- 组件写法见技能 `assets/components.md`:KPI 指标条、`> [!风险]/[!洞察]/[!提示]`
  提示框、数据表(表下来源行)、`![图题](outputs/charts/xx.png)` 图表。
- 图表不少 5 张(营收利润趋势、盈利能力、利润与现金流对比、费用结构、
  风险热力图为基线),优先 vivid-figures-skill 选配,一律 PNG。
- 表格行按数据增删,不硬凑;高风险内容用提示框,每个报告 4~6 处。

## 硬规则

1. 每个数字可溯源:年报页码、原始来源名称(企查查 / 智慧芽 / 同花顺,注明
   具体数据项如文书号、专利号),或网页 URL 与访问日期,三选一。
2. 报告正文不出现 MCP 工具名、服务器名(`qcc-*`、`hithink-*` 等)、
   `outputs/` 内部路径与脚本名——那是工作存档,读者只认原始来源。
3. 跨年比较先检查会计政策变更;口径变化要写明,不可机械横比。
4. 风险等级只有高 / 中 / 低,评分映射 56 / 20 / 4,不发明新等级。
5. 结论必须闭环:收入 → 扣非利润 → 现金流 → 资产回报 → 内控覆盖,逐条回答。

## 交付与自检

交付 `outputs/report.md`(版式由平台按模板主题导出 DOCX,不要手写 docx 转换脚本)。
交付前用平台工具 `check_report`(传入 markdown 与本模板契约)自检:
占位符残留、必备产物、章号连续、图表数、来源行、内部路径泄漏。
逐条通过后才交付。
