# 税务合规体检报告

写作指南。本模板是契约式:版式由渲染器统一生成,章节结构由你按证据组织。
契约约束「必须为真、必须包含」,不约束章节排布——结构相似,不雷同。

## 必答问题(报告必须逐条回答)

1. 体检主体、期间与税种范围是什么?
2. 五块自检(申报一致性、税负合理性、内控有效性、舞弊红旗、优惠备案)
   各自的评级与证据是什么?
3. 红旗项的管理层解释或待核验事项有哪些?
4. 整改清单(责任人、时限、优先级)是什么?
5. 结论与「非审计意见」边界如何声明?

## 必备产物(缺一不过质量门)

- 体检范围声明:主体、期间、税种、证据边界。
- 五块评级表:每块「评级(健康/关注/预警)、核心证据、来源」。
- 红旗清单:命中项逐条列「证据、管理层解释或待核验」;未命中写「未发现」。
- 整改清单:动作、责任角色、时限、对应红旗或评级项。
- 数据缺口:未获取的证据与原因。
- 免责声明:体检非审计意见,不构成申报口径承诺。

## 叙事脊柱(引导,不是硬性章节)

范围与口径 → 五块体检 → 红旗与解释 → 整改与结论

## 硬规则

1. 评级必须挂证据行,不得凭感觉;证据不足标「待核验」。
2. 每个数字、每条发现可溯源:原始来源名称(注明数据项)、政策文号 + 条款,
   或网页 URL 与访问日期。
3. 报告正文不出现 MCP 工具名、服务器名、outputs/ 等内部路径、/tmp/ 等临时路径与脚本名。
4. 拿不到的数据写「未获取」并写原因;转述标「转述」。
5. 图注统一「图表N + 标题 + 来源行」;不留草稿 / 待修改 / TODO 等未定稿标记。

## 交付与自检

交付 `outputs/report.md`;版式由平台渲染 DOCX,不要手写转换脚本。
Craft 沙箱内交付前用平台工具 `check_report` 自检并修完全部 FAIL 项。
