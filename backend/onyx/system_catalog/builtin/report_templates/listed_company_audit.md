# 上市公司财务审计报告

写作指南。本模板是契约式:版式由渲染器统一生成,章节结构由你按证据组织。
契约约束「必须为真、必须包含」,不约束章节排布——结构相似,不雷同。

## 必答问题(报告必须逐条回答)

1. 审计主体与口径(期间、币种、准则)是什么?
2. 勾稽检查是否通过,失败项有哪些?
3. 关键比率与同业对比结论如何?
4. 信用、司法、专利与研发线索说明了什么?
5. 红蓝复核还有哪些未关闭的质疑?
6. 结论是什么,哪些事项需进一步核实?

## 必备产物(缺一不过质量门)

- 主体与口径:官方名称、证券代码、交易所、统一社会信用代码;期间、币种、
  单位、会计准则;数据来源清单。
- 勾稽检查:净利润、未分配利润、货币资金;失败项写入发现表。
- 关键比率表:每项列公式、取数科目、本期值与对比期值。
- 行业与同业对比:指数、同业名单、对比口径。
- 信用与司法:诉讼、处罚、股权与经营风险,带来源。
- 专利与研发:仅引用已捕获的检索结果,附检索深度对账表。
- 数据问题:缺失、重述、口径变更。
- 结论与需进一步核实事项。

## 叙事脊柱(引导,不是硬性章节)

主体与口径 → 勾稽与比率 → 外部线索(信用/司法/专利) → 红蓝复核 → 结论

在此弧线内:章节可增删、合并、重命名;发现按严重程度组织,不按工具组织。

## 硬规则

1. 无来源的数字不得写入结论。
2. 未关闭的红蓝复核质疑不得写成结论。
3. 每个数字、每条发现可溯源:原始来源名称(注明数据项)或网页 URL 与访问日期。
4. 报告正文不出现 MCP 工具名、服务器名、outputs/ 等内部路径与脚本名。
5. 拿不到的数据写「未获取」并写原因;转述标「转述」。

## 交付与自检

交付 `outputs/report.md`;版式由平台渲染 DOCX,不要手写转换脚本。
Craft 沙箱内交付前用平台工具 `check_report` 自检并修完全部 FAIL 项。

## 组件与图表

- KPI 指标条:` ```kpi ` 围栏,每行 `指标 | 值 | 状态`;状态词 预警/恶化/偏高/偏低/关注
  显红,改善/达标/稳健 显绿,其余中性蓝。
- 提示框:`> [!风险] 标题`(红)、`> [!洞察] 标题`(蓝)、`> [!提示] 标题`(灰蓝),
  正文跟在后续 `>` 行。
- 数据表:GFM 表格;**表格下一行写来源**,每张表都要有。
- 图表:`![图题](outputs/charts/NN.png)` 独立成段,PNG 先行产出。

## 完成标准

- 无残留 {{占位符}}。
- 章号连续,标题按内容自拟。
- 无来源的数字不进结论;发现表无空行。
- 图表不少于 3 张。
