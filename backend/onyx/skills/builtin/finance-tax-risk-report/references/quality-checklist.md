# 交付自检清单

交付前逐条过。任何一条不过就修完再交付。其中「检查项」由平台工具
`check_report` 自动判定,其余为人工核对。本清单针对历史上手工成稿报告的
真实缺陷逐条设卡。

## 自动检查(check_report)

1. 零占位符残留(`{{...}}`)。
2. 必备产物齐全(看板 / 矩阵 / 整改 / 期后 / 缺口 / 来源 / 免责)。
3. 章号连续不重复不跳号(标题自编,一、二、… 或 1. 2. …,全文一种风格)。
4. 图表引用不少于契约下限(`![](...)` 计数)。
5. 有来源行(`来源: …第 X 页` / URL)。
6. 零内部路径泄漏(`outputs/`、`.opencode/`、MCP 工具名)。

## 数据

7. KPI 看板、三表透视、年报摘要三级对账一致;勾稽(未分配利润、资产=负债+权益、
   期末现金≈货币资金)通过。
8. 每个数字可溯源:年报页码、原始来源名称(企查查 / 智慧芽 / 同花顺,注明具体
   数据项如文书号、专利号),或网页 URL 与访问日期,三选一。
9. 拿不到的数据写「未获取」+ 原因。没有零填充、没有插值、没有臆造。
10. 转述数据标「转述」或「估算」;期后数据标「未经审计,仅作趋势观察」。
11. 跨年口径提示到位:会计政策变更、合并范围变化年份已标注不可机械横比。
12. 全文单位一致(亿元 / 百万元 / %),同一指标全文一个口径;图、表、KPI 条
    三处同指标同值。

## 结构与内容

13. 四幕脊柱完整:总览(含执行摘要与看板)→ 数据与趋势 → 风险(含矩阵)→
    建议与结论(含整改、期后、免责);章节标题按内容自拟,不要求固定章名。
14. 每条风险卡片三段式完整:数据证据(带数值与来源)→ 成因分析 → 潜在影响。
15. 整改三层(30 日 / 90 日 / 持续监控)齐全,且每条回扣风险编号。
16. 重大专题(投资成败、募投变更、审计机构更换、实控人变动等)已单独成节。
17. 结论给闭环主线,逐条回答必答问题;先安全垫、再否定「恢复=风险消失」。

## 合规

18. 免责声明完整保留在文末。
19. 无投资建议、无买卖点、无估值结论;风险表述自我设界(「可能」「或将」),
    无「必然」「肯定」式断言。
20. 引用的公告、新闻、政策均注明日期与 URL;不虚构案号、统一社会信用代码、
    专利号。
21. `outputs/` 交付物齐全:report.md、statements.json、kpi_dashboard.json、
    charts/、mcp 原始 JSON(存档与复核用,不出现在报告引用里)。
    DOCX 由平台按模板主题导出,不手写转换脚本。
